# Deployment environment reference

This file lists every environment variable used by `FlareTunnel-Manager` and the embedded FlareTunnel process.

> Do not commit real credentials. Store secret values in a protected `.env` file or in the secret manager provided by the VPS or PaaS.

================================

```env
MODE=use
```

Selects the manager operation.

Possible values:

- `create`: create enough `flaretunnel-*` Workers to reach each account's `target_workers` value.
- `use`: list existing FlareTunnel endpoints and start the authenticated proxy. This is the normal long-running deployment mode.
- `delete`: remove the requested number of existing `flaretunnel-*` Workers.

This variable is required and has no default value.

================================

```env
AUTH_PROXY={"username":"proxy-user","password":"CHANGE_ME"}
```

Required only when `MODE=use`. It contains the proxy username and password as one strict JSON object. Both values must be non-empty. Unknown JSON fields, malformed JSON, and trailing JSON data are rejected.

The manager converts `username:password` to Base64 and passes the result internally to FlareTunnel as `AUTH_PROXY_BASIC`. For example:

```text
proxy-user:CHANGE_ME
→ Base64
→ cHJveHktdXNlcjpDSEFOR0VfTUU=
```

Do not configure `AUTH_PROXY_BASIC` manually. It is an internal child-process variable generated by the manager.

================================

```env
PORT=8080
```

TCP port on which FlareTunnel listens for HTTP and HTTPS proxy traffic.

Possible values: an integer from `1` to `65535`.

Default value: `8080`.

================================

```env
FLARETUNNEL_MODE=random
```

Selects how FlareTunnel rotates requests between available Workers.

Possible values:

- `random`: select Workers randomly.
- `round-robin`: rotate through Workers sequentially.

Default value: `random`. Unknown values fall back to `random`.

================================

```env
FLARETUNNEL_BLACKLIST=minimal
```

Selects the blacklist shipped inside the Docker image.

Possible values:

- `minimal`: `/opt/flaretunnel/blacklist-minimal.txt`.
- `full`: `/opt/flaretunnel/blacklist.txt`.
- `aggressive`: `/opt/flaretunnel/blacklist-aggressive.txt`.

Default value: `minimal`. Unknown values fall back to `minimal`.

The manager does not accept an arbitrary blacklist path and does not support `FLARETUNNEL_BLACKLIST_DIR`.

================================

```env
CF_USE_ACCOUNTS=[{"name":"main","api_token":"CLOUDFLARE_API_TOKEN","account_id":"CLOUDFLARE_ACCOUNT_ID"}]
```

Required when `MODE=use`. JSON array of Cloudflare accounts used to discover existing `flaretunnel-*` endpoints.

Each account requires:

- `name`: local account name;
- `api_token`: Cloudflare API token;
- `account_id`: Cloudflare account identifier;
- optional `zone_id`: Cloudflare zone identifier.

`target_workers` is not required in `use` mode.

================================

```env
CF_CREATE_ACCOUNTS=[{"name":"main","api_token":"CLOUDFLARE_API_TOKEN","account_id":"CLOUDFLARE_ACCOUNT_ID","target_workers":10}]
```

Required when `MODE=create`. JSON array of accounts whose final number of `flaretunnel-*` Workers must reach `target_workers`.

`target_workers` must be a non-negative integer. The manager calculates the missing number from the actual Cloudflare state and retries reconciliation at most three times per account.

================================

```env
CF_DELETE_ACCOUNTS=[{"name":"main","api_token":"CLOUDFLARE_API_TOKEN","account_id":"CLOUDFLARE_ACCOUNT_ID","target_workers":10}]
```

Required when `MODE=delete`. JSON array of accounts from which the manager should remove the requested number of `flaretunnel-*` Workers.

`target_workers` is the number to delete, not the desired final population. It must be a non-negative integer. Cleanup is always bounded and uses `--count N --yes`.

================================

```env
CF_API_BASE_URL=https://api.cloudflare.com/client/v4
```

Optional Cloudflare API base URL override.

Default value:

```text
https://api.cloudflare.com/client/v4
```

Use the default in production. This variable is useful for controlled testing with a compatible mock API.

================================

```env
FLARETUNNEL_BINARY=/usr/local/bin/flaretunnel
```

Optional path or executable name for the FlareTunnel binary launched by the manager.

Default value: `flaretunnel`.

The official Docker image already contains the binary at `/usr/local/bin/flaretunnel`; therefore this variable normally does not need to be set. It is useful for local development or controlled tests.

================================

## Recommended `MODE=use` deployment example

```env
MODE=use
AUTH_PROXY={"username":"proxy-user","password":"REPLACE_WITH_A_STRONG_PASSWORD"}
PORT=8080
FLARETUNNEL_MODE=random
FLARETUNNEL_BLACKLIST=minimal
CF_USE_ACCOUNTS=[{"name":"main","api_token":"REPLACE_WITH_A_CLOUDFLARE_TOKEN","account_id":"REPLACE_WITH_A_CLOUDFLARE_ACCOUNT_ID"}]
```

## Variables that must not be configured manually

```text
AUTH_PROXY_BASIC
FLARETUNNEL_BLACKLIST_DIR
```

`AUTH_PROXY_BASIC` is generated internally by the manager and injected only into the FlareTunnel child process. The blacklist directory is fixed inside the image so that deployment selects only a reviewed blacklist level.

## Deployment notes

- Use exactly one active account variable according to `MODE`.
- Keep API tokens and `AUTH_PROXY` in a secret manager or a file with restrictive permissions.
- Do not commit `.env` files containing real values.
- In `MODE=use`, expose the value of `PORT` through Docker, the VPS firewall, or the PaaS networking configuration.
- The Docker image embeds the three blacklist files and builds the FlareTunnel fork at commit `b308a52ce3eb775c13744b23f2024bead88a4c99`.
